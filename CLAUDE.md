# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

MMTVL is a personal, native macOS media launcher styled after tvOS. It runs full screen on a Mac mini (HDMI → AV receiver → TV) and is driven by a remote, keyboard/mouse, or phone. It launches external apps (Plex HTPC, Prime Video, a browser) and has built-in YouTube (TV UI) and IPTV experiences.

**Start every task by reading `docs/plans/MASTER_PLAN.md`.** It holds the goals, architecture decisions (D1…), and milestone status. Work is driven by per-milestone sub plans in `docs/plans/`.

## Planning workflow

- `/plan-milestone M<n>`: research and write a detailed sub plan (`docs/plans/M<n>-<slug>.md`) from `docs/plans/TEMPLATE.md`. Planning only, no app code. Best run with a strong model / high effort.
- `/build-plan docs/plans/M<n>-<slug>.md`: implement a sub plan step by step. It can run on a smaller model / lower effort.
- When implementing: follow the sub plan, tick its checkboxes, and keep the milestone status in the master plan current. Don't redesign. If the plan is wrong or ambiguous, record it under *Deviations & questions* in the sub plan and ask.
- Architecture-level changes must be reflected in the master plan's decisions table (§4).

## Project setup notes

- Xcode project with **file-system-synchronized groups**: any file placed under `MMTVL/` or `MMTVLTests/` is automatically part of that target. Don't add file references to `project.pbxproj` by hand. It only needs editing for build settings, new targets, or Swift package dependencies.
- No `Info.plist` file: it is generated from `INFOPLIST_KEY_*` build settings. Add Info.plist keys there.
- Swift 6 with **`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`**: types are main-actor by default. Mark pure models/helpers `nonisolated` when they must be used off the main actor.
- `NSLocalNetworkUsageDescription` (M7 L17, `INFOPLIST_KEY_NSLocalNetworkUsageDescription`; M7b: the text also mentions casting): outgoing connections to the Plex Media Server on the LAN, and the YouTube casting responder's multicast (receiving SSDP on UDP 1900, answering by unicast), need macOS's Local Network permission (System Settings → Privacy & Security → Local Network → MMTVL). Incoming phone remote and DIAL HTTP connections don't.
- Not sandboxed, no hardened runtime. Signed `Apple Development` with the personal team **H846CY8RB4** (no provisioning profile needed), so the Accessibility (TCC) grant for the global event tap and AX full screen survives rebuilds. To re-test onboarding: `tccutil reset Accessibility dev.mmtvl.launcher`.
- Deployment target: macOS 26.0. Bundle ID: `dev.mmtvl.launcher`.
- Version and build (M7c L28): `MARKETING_VERSION` is set by hand (1.1.0 from M7c); `CURRENT_PROJECT_VERSION` goes up by 1 for **every build given to the user** (`scripts/test-build.sh` does it), so the installed build is always identifiable (Settings → About, and under the home clock). Never reuse or reset a build number.
- App icon: `Assets.xcassets/AppIcon` is the user's "tv" logo cropped square and masked to the macOS icon shape (824-point continuous rounded square with a soft shadow on a transparent 1024 canvas; macOS 27 shows it without the gray tile). `Assets.xcassets/Logo` is the same logo full-bleed (1024 × 1024, no rounded corners) for places that round it themselves (the phone remote's home-screen icon, M7b). Source: `~/Downloads/mactvlogo.jpeg` (2026-10-06), not in the repo.
- Tests use Swift Testing (`import Testing`, `@Test`, `#expect`), hosted in the app (`@testable import MMTVL`).
- Swift packages (M4): **MPVKit 1.0.0** (the LGPL `MPVKit` product only, never `MPVKit-GPL`; `import Libmpv`) and **GRDB 7.11.x**, linked to the **app target only**. Tests reach them through app types (`EPGStore.inMemory()`), never by importing them. `MMTVL.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved` is committed. The first resolve downloads about 350 MB of MPVKit binaries. `MPVVideoView.swift` shows OpenGL deprecation warnings by design (D22). Multiview (M6) runs up to 5 mpv players, one per window, from a pool in `LiveTVModel` that is reused and never torn down.

## Conventions

- Logging: `os.Logger(subsystem: "dev.mmtvl.launcher", category: "<Component>")`.
- Secrets (IPTV URL/credentials, PINs) go in the Keychain via `App/Keychain.swift`: the **legacy login keychain**, service `dev.mmtvl.launcher` (never `kSecUseDataProtectionKeychain`, which fails with -34018 without a provisioning profile). The launcher PIN (D20) is account `launcher-pin`. Forgotten PIN, from the Mac: `security delete-generic-password -s dev.mmtvl.launcher -a launcher-pin`. The Live TV playlist URL is account `iptv-playlist-url`; the pasted guide URLs (M6b, up to 6, in priority order) are account **`iptv-guide-urls`**, a JSON array (M4's single `iptv-guide-url` is migrated on the next save and removed). All are pasted from the clipboard in Settings → Live TV. They carry account tokens: **never log or show a full IPTV source or stream URL**, only its host. Exception (M6b L2): Settings may show a guide's file name when it looks like a guide file (`.xml`, `.xml.gz`, `.gz`, at most 64 characters), never its query; logs still show the host only. Paired phones (M5) are account `phone-remote-phones`: a JSON array of names and token SHA-256 hashes (never the tokens). Reset from the Mac: `security delete-generic-password -s dev.mmtvl.launcher -a phone-remote-phones`. Plex (M7, D28) is account `plex-token` (the plex.tv user token, from Settings → Plex → Sign In at plex.tv/link) and account `plex-server-token` (the chosen server's access token); Settings → Plex → Sign Out removes both. From the Mac: `security delete-generic-password -s dev.mmtvl.launcher -a plex-token` and `… -a plex-server-token`. **Never log Plex tokens, link codes or full connection URIs** (server name and URI host only). Non-secret config is JSON in `~/Library/Application Support/MMTVL/`, read at launch. Missing files are written with defaults; a corrupt file is moved to `<name>.bak` and replaced with defaults:
  - `launch-items.json`: home screen tiles, in order. Per item, optional `launchFullScreen` (D15), `isHidden` and `requiresPIN` (D20; Settings and Exit to Desktop always ask when a PIN is set). Optional `artStyle` (M7 L24): `"icon"` for the app icon on a blurred backdrop; missing = designed art. Chromium web app tiles (PWAs, M7 L23) may have `startURL` (e.g. `"startURL": "https://meet.google.com/home?calling=1"`, set in Settings → the tile → Start Page): MMTVL then asks the browser to open the web app on that page; it must be on the app's own site.
  - `settings.json`: `globalInputEnabled`, `controllersEnabled`, `cursorAutoHide`, `launchAtLogin` (kiosk mode only). Optional hand-edited `youtubeUserAgent` overrides the YouTube TV user agent (D21). `phoneRemoteEnabled` (Settings → Phone Remote). Hand-edited `phoneRemotePort` (default 8765, the page; the WebSocket uses port + 1; outside 1024…65534 falls back to 8765) and `phoneRemoteVolume` (`auto` | `keys` | `system` | `app`, D25; unknown values read as `auto`). `keyBindingsRevision` (M7 L7): which default bindings `key-bindings.json` has seen; a file without it is revision 1 and gets the Menu/Channel defaults added once at the next launch. `channelUpMovesUpList` (M7 L22, Settings → Remote & Input → Channel Up; default `true`: Channel Up zaps up the channel list like the Up arrow; `false`: to the higher channel number). `youtubeCastEnabled` (M7b, Settings → Casting; default `true`), `castDeviceID` (the DIAL device uuid, made once at launch; hand edits change how phones list MMTVL) and `reflectorAutoStart` (M7b, Settings → Casting → Android; default `true`). `kioskLock` (M7c D36, Settings root → Keep Other Apps Out; default `true`) and `homeLivePreview` (M7c D37, Settings → Live TV → Preview on Home; default `true`). `showVersionOnHome` (M7c L28, Settings root → About; default `true`): "Version 1.1.0 Build N" under the home clock. `homeStartTile` (M7c L32, Settings → Edit Home Screen → a tile → Start Here; default `"plex"`): the tile focused at launch and after every Home press (a missing or hidden tile: the first tile). Missing keys use defaults.
  - The **Settings screen** (the Settings tile, which is always on the home screen and can be moved but not hidden or removed) edits `settings.json`, `launch-items.json` and (Remote Buttons, M7) `key-bindings.json` live and saves each change at once. Hand edits made while MMTVL runs are overwritten by the next Settings change, so edit those files with MMTVL quit. Settings → Relaunch MMTVL picks up hand edits.
  - `iptv-state.json`: Live TV's last channel and group, `guideImports` (guide id = SHA-256 of its URL → last successful import; replaces M4's `lastGuideImport`/`lastGuideSourceHash`, which are ignored), and the Multiview snapshot `multiview` (layout, channel ids per window, highlighted window, whether Live TV was left in Multiview). An undecodable snapshot reads as none. `recentChannelIDs` (M7 L13): up to 10 channels watched, most recent first; the home screen's Live TV "On Now" shelf uses them when there are no favorites. Hand edits are fine while MMTVL is quit.
  - `epg-overrides.json` (M4 L17): `{ "<channel name or tvg-id>": "<EPG channel id>" }` for channels the guide doesn't match by id or exact name. Keys match the playlist's channel name first, then its `tvg-id`, ignoring case. A value of `""` means no guide. Also written by Live TV's **Match Guide** (M6b: in the guide, Left on the programme airing now, Select, Match Guide), keyed by channel name; *Automatic* removes the channel's keys. Hand edits: Settings → Live TV → Refresh Now applies them (no relaunch); edit with MMTVL quit, since Match Guide rewrites the file. To find EPG ids: `gzip -dc guide.xml.gz | grep -o '<channel id="[^"]*"'`.
  - `iptv-channels.json` (M6b L5): `favorites` (channel ids, in order), `hiddenChannels` (channel ids), `hiddenGroups` (group names as in the playlist). Set from the guide's channel menu and Settings → Live TV → Groups / Hidden Channels. Ids not in the playlist are kept and ignored. Hand edits while MMTVL is quit. Kept by Remove Live TV Source.
  - `guide.sqlite` (+ `-wal`/`-shm`): the EPG cache (GRDB, D8). Rows are per guide (`sourceID` = SHA-256 of the guide URL, D26). Safe to delete; the next guide refresh rebuilds it. Channels are never stored; the playlist is re-fetched at launch and when Live TV opens (D23).
  - `plex.json` (M7 L15): `clientIdentifier` (a UUID made once; plex.tv lists this Mac as "MMTVL" under Authorized Devices), `serverID`/`serverName` (the chosen server), `connections` (its https, non-relay URIs, local first; MMTVL never uses http or relay connections, D28) and `lastConnection`. Sign Out resets it except `clientIdentifier`. Hand edits while MMTVL is quit.
  - `tile-art/` (M7 L3): custom tile pictures, `<tile id>.png` (or `.jpg`, `.jpeg`, `.heic`, case-insensitive), ideally 5:3 (e.g. 1500 × 900). Picked up when the home screen appears. **Settings → a tile → Tile Art** chooses the style (Designed / App Icon) or copies a picture from Downloads, Pictures or Desktop into this folder (the first listing asks macOS for Downloads/Desktop access: `NSDownloadsFolderUsageDescription`, `NSDesktopFolderUsageDescription`), and removes it. Without a picture, apps get **designed art drawn by MMTVL** (D29; no logo files in the repo): M7c L33 **glyph art** when the icon has a plain background (`IconBackground`: the tile continues the icon's background and the icon's shape edge is faded out, tvOS style), else brand colors from `Launcher/AppArtCatalog.swift` or colors taken from the icon, plus the app's own icon. Built-ins get their gradient. A picture with transparent or plain edges counts as a logo (`PictureEdges`) and is padded on that color (dark or light for a transparent one); other pictures show whole over a blurred copy. Choosing Designed or App Icon removes the tile's picture. Created empty at launch.
  - `key-bindings.json`, edited in **Settings → Remote Buttons** (M7, D27): *Add a Button* learns the next key, media key or controller button (never ⌘-combos; phone buttons can't be learned), each button can be removed (not the last one of an arrow, Select or Back), Home buttons can *Work in Other Apps*, and *Restore Default Buttons* resets everything. Changes apply and save at once, so hand edits only with MMTVL quit. The file is an array of `{ "trigger", "command", "isGlobal", "label" }`. Commands: `up`, `down`, `left`, `right`, `select`, `back`, `home`, `playPause`, `fastForward`, `rewind`, and from M7 `menu` (the channel menu in Live TV, the window menu in Multiview), `channelUp`, `channelDown` (zap; page through lists). Triggers are `{"key": {"keyCode": 115, "modifiers": []}}`, `{"media": {"key": "playPause"}}` or `{"controller": {"button": "a"}}` (buttons include `leftTrigger`/`rightTrigger` from M7). Modifiers must match exactly. `isGlobal` bindings also act while another app is frontmost (keys need Accessibility). To find a new remote's key codes, run the `log stream` command above with MMTVL frontmost and press the buttons: each unbound key logs `Unbound key <code> modifiers [...]`.
- YouTube (D5, D21) is `youtube.com/tv` in one persistent WKWebView (`YouTube/`). Its website data (sign-ins, profiles, Parent code) is in `~/Library/WebKit/dev.mmtvl.launcher/WebsiteData`; Settings → Sign Out & Clear YouTube Data wipes it. In Debug builds, Safari → Develop → this Mac inspects the YouTube page.
- Phone remote (D11, D24, M5) lives in `RemoteServer/`: plain HTTP on `phoneRemotePort` serves the page, a WebSocket on port + 1 carries the remote. The phone opens `http://<Mac IP>:8765/`, so give the Mac mini a DHCP reservation on the router. Pairing is only on Settings → Phone Remote → Pair a Phone (QR code + 4-digit code). The page has CH −, Menu and CH + buttons (M7); in other apps CH ± send Page Up/Down and Menu does nothing. The page's files are in `MMTVL/RemoteServer/Web/` (`remote.html/.css/.js`, unique names because they ship flat in `Contents/Resources`); `RemoteWebAssets` allow-lists them. M7b: the home-screen icon is the `Logo` asset rendered in code (`PhoneRemoteIcon`) at `/apple-touch-icon.png` and `/apple-touch-icon-precomposed.png` (180), `/icon-192.png`, `/icon-512.png`, plus `/remote.webmanifest`. The page's **Trackpad** button (remembered in the phone's `localStorage` `mmtvl.mode`) sends `{type:"pointer",dx,dy}`, `{type:"scroll",dx,dy}` (CSS pixels, at most 1000 per message) and `{type:"click",button:"left"|"right"}`; `Input/PhonePointer.swift` accelerates, clamps to the displays and counts double/triple clicks. **Never log tokens, pairing codes, typed text or raw messages.**
- Synthetic input (M5 L6): phone keys for other apps, phone text and (M7b) the phone trackpad's mouse moves, clicks and scrolls are posted by `Input/SyntheticInput.swift`, tagged with `eventSourceUserData = SyntheticInput.marker`. MMTVL's input code (`InputRouter`'s local monitor, `GlobalEventTap`) must keep passing `SyntheticInput.isOwn` events through untouched, or typed Delete becomes Back.
- UI is designed on a 1920×1080-point canvas (a 4K TV in HiDPI mode) and scaled to the screen. Use the tokens in `DesignSystem/Theme.swift`, not literals. The look is tvOS 26/27 **Liquid Glass** (D29): use `.glassPanel()` / `.glassPanel(in:)` for panels and `.glassRim(cornerRadius:isFocused:)` for tiles and cards (`DesignSystem/Glass.swift`); with Reduce Transparency panels become solid. Focused list rows stay bright white for legibility.
- **Casting (M7b, D30–D32)** lives in `Cast/`. YouTube: MMTVL answers DIAL itself, SSDP on **UDP 1900** (`SSDPResponder`, shared with other SSDP users through `SO_REUSEPORT`) and HTTP on **TCP 8770** (`DIALServer`; any free port if 8770 is taken, the SSDP reply names the real one), owned by `CastReceiver` (restarts on network change and wake). `/apps/YouTube` requests go to **leanback's own handlers** through the `h5vcc.dial.DialServer` shim injected into the YouTube page (`YouTube/YouTubeDIAL.swift`; only when casting is on when the web view is created) once leanback has registered (warm path); otherwise MMTVL answers `stopped` and a launch opens `youtube.com/tv?<allowed launch parameters>` (cold path). A cast switches the TV to YouTube from any screen or app and ignores the YouTube tile's PIN. Requests with an http(s) `Origin` get 403; **never log DIAL bodies, queries or pairing codes**. Settings → Casting shows YouTube (toggle + state), AirPlay Receiver (loopback probe of port 7000; Select opens System Settings → AirDrop & Handoff), Android (Reflector) and Plex HTPC (running or not). Test with the `curl` lines above, or an M-SEARCH: `python3 -c 'import socket;s=socket.socket(socket.AF_INET,socket.SOCK_DGRAM);s.settimeout(3);s.sendto(b"M-SEARCH * HTTP/1.1\r\nHOST: 239.255.255.250:1900\r\nMAN: \"ssdp:discover\"\r\nMX: 1\r\nST: urn:dial-multiscreen-org:service:dial:1\r\n\r\n",("239.255.255.250",1900));print(s.recvfrom(2048)[0].decode())'`.
- **Reflector (M7b, D32):** Android screen mirroring goes through Reflector 4 (bundle id `com.squirrels.Reflector-4`, to be confirmed in M7b step 7). With `reflectorAutoStart`, MMTVL starts it hidden at launch and after wake and restarts it 5 s after it quits (at most 3 times in 10 minutes). `ReflectorMonitor` polls Reflector's on-screen windows once a second (`CGWindowListCopyWindowInfo`, no Screen Recording needed): a window at least 25 % of the screen's width and height is a mirroring session; MMTVL then leaves Live TV/YouTube like Home, brings Reflector forward and makes it full screen (AXFullScreen). When the session ends MMTVL shows its home screen (unless the user switched to another app). **Home during mirroring ends it** (the window's AX close button, else ⌘W sent to Reflector); a YouTube cast ends it too. Reflector's preferences are a manual checklist (Settings → Casting → Android footer): Advanced: AirPlay off, Google Cast on; General: Always on Top off, Show Client Name off; Connection: Display Fullscreen on, no connection prompt; receiver name "MMTVL Screen Mirroring"; device frame off (⌘B); allow Reflector under Privacy & Security → Local Network. macOS's AirPlay Receiver stays on for iPhones.
- All input flows through `InputRouter` as `RemoteCommand`s. Screens handle commands, not raw key events. While Settings → Remote Buttons learns a button, `InputRouter.captureHandler` takes the next trigger instead (local monitor, event tap and controllers all honor it; ⌘-combos always pass through).
- Home screen (M7): rows scroll when there are more than two (`Launcher/HomeLayout.swift`; the mouse wheel moves focus by a row); the focused tile has the parallax effect (`DesignSystem/ParallaxFocus.swift`, off with Reduce Motion); the focused tile's art fills the screen behind the tiles (`ShelfBackdrop`, L27; M7c: color and blur only, no big app icon), and the **top shelf** (`Launcher/TopShelf*.swift`, D28) shows over it; Up from the first row enters it. M7c (D38): the tvOS 26 layout, **six tiles per row**, row 0 in a **glass dock** low on the screen (`Theme.homeFirstRowTop`), the next row peeking at the bottom, titles only under the focused tile; Down scrolls into a grid with the hero dimmed. The hero's logo/title, subtitle and time left sit **top-left** (`ShelfCarouselInfo`), page dots above the dock. **Live TV** is a page carousel of channels (the default channel first, then favorites or recents; no auto-advance; Left/Right in the hero switch the muted preview). Select on Live TV or a Plex page **animates the home UI away** (0.45 s) before opening (Live TV adopts the preview's stream). Custom tile pictures show whole over a blurred copy of themselves. M7c (D37): with the **Plex** tile focused, Continue Watching is a full-screen **carousel** (`Launcher/ShelfCarouselView.swift`: 1920 × 1080 art, crossfade every 8 s with a slow zoom, the clear logo or title, time left, page dots; Up enters, Left/Right wrap, Select opens Plex HTPC). The Live TV preview (the focused page's channel, else the last channel or Multiview's highlighted window) plays **muted** on pool player 0, without a sleep assertion, and **preloads on the whole home screen** (M7c L25: drawn only while the Live TV tile is focused); Select adopts that stream (no reconnect), and leaving Live TV keeps a single playing channel running as the preview. It stops when another screen opens, MMTVL isn't active, the displays sleep, the screen saver starts, or after 10 minutes without input. Channel logos (guide, banner, Live pages) come from `IPTV/ChannelLogoCache.swift` (M7c L24): memory plus `~/Library/Caches/dev.mmtvl.launcher/ChannelLogos/` (files named by the URL's SHA-256; safe to delete).
- **Foregrounding (M7c, D35):** every "show MMTVL" (Home, wake, an app quitting, cast/mirroring end, the kiosk guard) goes through `App/Foregrounder.swift`, which checks that MMTVL became frontmost and climbs `NSApp.activate()` → AX `kAXFrontmostAttribute` → hiding the frontmost regular app (it keeps running; its tile brings it back). In `-windowed` mode only the first rung runs. Item 20: the Dock can stay on a quit full-screen app's dead Space (Plex HTPC after Exit) with MMTVL frontmost behind it. The cause was MMTVL's stored presentation options, which macOS applied when it activated MMTVL mid-animation; so MMTVL clears them while in the background and sets them 1 s after becoming active (the mini has the Dock and menu bar set to hide automatically in System Settings, so nothing flashes meanwhile); half a second after each show it checks that its window is on the active Space and visible, and if not it restarts the Dock, at most once a minute (category `KioskWindowController`). By hand, from SSH: `killall Dock`. Phone commands that arrive while MMTVL's window shows but MMTVL isn't active (Finder or nothing in front) bring it forward first and go to MMTVL.
- **Kiosk lock (M7c, D36)**, kiosk mode with `kioskLock` on and the event tap running: while MMTVL is active, presentation options disable ⌘Tab, Force Quit (⌥⌘Esc) and ⌘H; with another app in front the event tap consumes ⌘Tab, ⌘⇧Tab, ⌘\`, ⌘Space, ⌥⌘Esc and ⌃arrows (`App/KioskLock.swift`), and the **kiosk guard** takes the screen back (like Home) when a regular app MMTVL didn't open comes forward. Allowed: the app a tile opened (and a web app's browser) until the next Home, Reflector, and System Settings when MMTVL opened it. After 3 takebacks in 10 s the guard stops until the next Home. ⌘Q and the Dock's Quit ask for the PIN ("Enter PIN to quit MMTVL"; without a PIN they quit). Logout/shutdown and Settings → Relaunch MMTVL always quit. **Getting out:** Exit to Desktop (PIN), after which ⌘Tab, Finder and ⌘Q work normally until Home brings MMTVL back; or Settings → Keep Other Apps Out → Off; or, with MMTVL quit, set `"kioskLock": false` in `settings.json`.
- **Siri Remote through Remote Buddy (M7c L5):** in Remote Buddy's global (all-apps) behavior, map the TV/Home button to the keyboard **Home** key (key code 115, MMTVL's default global Home; the event tap consumes it, so apps never see it), Back/Menu to **Escape**, Select to **Return**, the arrows to the arrow keys and Play/Pause to the media play/pause key. Esc stays the app's own Back. If Remote Buddy sends something else, Settings → Remote Buttons → Home → Add a Button learns it, and Work in Other Apps makes it global. Plex HTPC embeds HIDRemote and may ask Remote Buddy to lend it the remote exclusively while it's in front; then the TV button never reaches MMTVL (Q21, the Remote Buddy setting that stops it is still to be recorded). On the mini (2026-10-10), Remote Buddy's mapping didn't reach MMTVL; the TV button works as Home because MMTVL learned it as **controller A** (Settings → Remote Buttons → Home, Work in Other Apps), so Game Controllers must stay on. The phone's Home button doesn't depend on this.
- **Browser tile (M7c L10):** after making a browser tile full screen (default browser or `url` tiles with `launchFullScreen`), MMTVL turns on View → **Always Show Toolbar in Full Screen** through Accessibility (`Launcher/BrowserToolbar.swift`; only if unchecked; retries for 5 s on a cold launch), so tabs and the address bar show. Never for web app tiles.
- **Live TV stream start (M7c L29):** the provider's stream URLs redirect (~0.5 s) to a CDN, and mpv and ffmpeg would each follow the redirect. `IPTV/Player/StreamResolver.swift` follows it once with URLSession and remembers the CDN address for 60 s; the player loads that address. Live TV resolves the channels one zap away after each channel starts, and the home screen resolves the first Live pages. A stream error drops the remembered address before the retry. `MPVOptions` sets `demuxer-lavf-o=http_multiple=0`. **mpv loads through a loopback relay** (D39, `IPTV/Relay/HLSRelay.swift`, 127.0.0.1 on any free port, started at launch): it fetches with kept-alive connections, rewrites playlist URIs to itself (`/r/<token>/<name>`, only registered URLs are served) and prefetches each stream's media playlists and start segment in parallel, so a channel starts in ~0.4 s. The guide's highlighted channel (resting 0.4 s) is warmed the same way before Select (M7c L31). The player's last retry goes straight to the CDN. Never log relay tokens or upstream URLs.
- **Live TV keys (M7c L11):** in the player, Select shows the info banner and timeshift bar (again hides them), Back hides them or opens the guide; in the guide, Back leaves Live TV (after closing the group list). Multiview windows touch, with no gaps.
