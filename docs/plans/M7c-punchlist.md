## Goal

Found while testing on the TV, fixed before the M8 release. **Home always works:** the phone's Home button, a keyboard's Home key and the Siri Remote's TV button (through Remote Buddy) bring MMTVL back from every app, including **Plex HTPC**, which stays running so it resumes instantly instead of being quit through its exit menu, and full-screen FaceTime, App Store and web apps. The remote keeps working afterwards. **MMTVL can't be left by accident:** ⌘Tab, ⌘Q, ⌘H, Force Quit and the Dock don't drop you on the desktop. The only way out is Exit to Desktop, with the PIN when one is set. The browser tile opens full screen **with its tabs and address bar showing**. In Live TV, **Back** brings up the guide, and Back in the guide leaves Live TV. Multiview windows touch, with no gaps between them. The home screen's full-screen backdrop no longer shows a big app icon. With the **Plex** tile focused, Continue Watching plays as a **full-screen carousel** of each item's art, fading from one to the next as on tvOS 27. With the **Live TV** tile focused, the **last channel plays muted** behind the tiles, and Select goes straight to it full screen with no reconnect.

## Out of scope

- **Esc as Home in other apps.** Esc and the phone's Back stay the app's Back (user choice 2026-10-09). Home comes from the phone's Home button, the Home key, or the Siri Remote's TV button mapped in Remote Buddy (L5).
- **Alerts and notifications inside apps** (FaceTime calls, Google Meet join requests, permission dialogs): the user hasn't tested these yet. Step 13 only checks what already works (Q18). Building anything waits for those results.
- Deep-linking a Plex carousel item into Plex HTPC (Q11). Select opens Plex HTPC, as the M7 cards do.
- Video previews for tiles other than Live TV (YouTube, Plex trailers).
- Making other apps' notification banners or system dialogs remote-navigable.

## Research & findings

### Home not returning from most apps (items 1, 2, 3)

- **Cooperative activation (macOS 14+).** `NSApplication.activate()` is a request: "calling this method doesn't guarantee app activation". `activateIgnoringOtherApps` no longer has any effect on macOS 14 and later. `NSRunningApplication.activate(from:options:)` returns `false` when the system refuses ([Apple: activate()](https://developer.apple.com/documentation/appkit/nsapplication/activate()), [Apple: cooperative activation](https://developer.apple.com/documentation/appkit/passing-control-from-one-app-to-another-with-cooperative-activation), [Apple: activate(from:options:)](https://developer.apple.com/documentation/appkit/nsrunningapplication/activate(from:options:)), [forum 793253](https://developer.apple.com/forums/thread/793253)). The current Home path, `KioskWindowController.show()`, calls only `NSApp.activate()` and never checks whether it worked.
- **D15 puts launched apps in native full-screen Spaces** (`WindowFullScreener` sets `AXFullScreen`; Chromium gets `--start-fullscreen`). The kiosk window lives on the desktop Space (`collectionBehavior = [.fullScreenNone]`), so going Home from a full-screen app means activating *and* switching Spaces. M5's spike only checked phone Home with **Terminal** (a normal window) in front, and that worked (M5 *Deviations*). FaceTime, App Store and the web apps (made full screen through AX) and Plex HTPC (native full screen by itself, see *Plex HTPC* below) all fail.
- **Hypothesis (step 2 confirms it):** the activation is refused or lands on the wrong Space. That covers item 1 (Home did nothing), item 2 (the same apps) and item 3: after Plex closed, MMTVL's window was visible but MMTVL wasn't active, so the cursor stayed and phone commands went out as synthetic keys to "the frontmost app" (`PhoneRemote.route` checks `NSApp.isActive`). A real mouse move, which is user input, let the activation complete.
- **What can take the foreground from the background** (each is **unverified** for this case until step 2):
  1. `NSApp.activate()`, then check `NSWorkspace.shared.frontmostApplication == .current` after a short delay.
  2. Accessibility: `AXUIElementSetAttributeValue(AXUIElementCreateApplication(getpid()), kAXFrontmostAttribute, true)`. MMTVL is already trusted (D4).
  3. Hide the frontmost app (`NSRunningApplication.hide()`). macOS then activates the next app, normally MMTVL. The app keeps running (D18 holds), and the next launch from its tile unhides it.
  4. Let the kiosk window join the active Space: add `.canJoinAllSpaces` + `.fullScreenAuxiliary` to its collection behavior, so it can appear over a full-screen app without a Space switch.
  - Not used: `SetFrontProcessWithOptions` (deprecated) and private SkyLight calls.
- **Keyboard Esc is Back, not Home.** It's `kVK_Escape → .back`, not global. The only default global Home bindings are the **Home key** (`kVK_Home` = key code **115**, fn+← on a Mac keyboard) and the controller's Home/Menu buttons (`Input/KeyBindings.swift`).

### Plex HTPC (item 11, added 2026-10-09)

The user reports that Home **never** works in Plex HTPC. Pressing Back repeatedly reaches Plex's exit menu, which **quits** Plex, so the next launch is a slow cold start. What the installed app shows (Plex HTPC 1.71.1, `tv.plex.htpc`, read from the dev Mac's bundle and `~/Library/Application Support/Plex HTPC/`):

- It's a **Qt 6 + mpv** app that uses **native macOS full screen** (`toggleFullScreen:`, `customWindowsToEnterFullScreenForWindow:`). `plex.ini` `[ui] windowStates=4` is Qt's `WindowFullScreen`, so Plex reopens in its own full-screen Space by itself. This is the same Space problem as FaceTime (item 1). The earlier assumption that "Plex seemed to work" was wrong.
- It embeds **HIDRemote** (`HIDRemote`, `exclusiveLockLendingEnabled`, `hidRemote:lendExclusiveLockToApplicationWithInfo:`, "Lost access … to IR Remote Receiver(s) … please quit other apps trying to use the Remote exclusively"). HIDRemote apps ask remote drivers such as Remote Buddy to **lend them the remote exclusively** while they're frontmost. If Remote Buddy lends it, Plex gets the remote's raw buttons directly and Remote Buddy's mapping (L5) never runs. Then the TV/Home button can't reach MMTVL however MMTVL is built. Plex's own `apple-remote.json` maps Menu to `back` and has no Home. Whether Plex HTPC's HIDRemote sees the **Siri Remote** (Bluetooth), or only IR Apple Remotes, is **unverified** (Q21).
- Plex's default keyboard map (`Resources/inputmaps/keyboard.json`): `Esc`/`Backspace` short = `back`, long = Plex's own `home`; `Home` = `step_backward`; `E` = `exit`. MMTVL's event tap consumes the Home key (global binding) before Plex sees it, so Plex's `step_backward` never fires. Custom maps go in `~/Library/Application Support/Plex HTPC/inputmaps/` (a copy of a default map with the same `name` overrides it). Plex has no setting to turn its Apple Remote handling off (no such key in the binary or `plex.ini`).
- Plex HTPC can be hidden (`NSRunningApplication.hide()`) and keeps running. `openApplication` from its tile unhides and activates it, so playback state and the Plex UI are where they were. That is D18's fast return.
- **Unverified:** whether Plex turns on Secure Event Input (it reacts to "SecureInput change notification"; it doesn't import `EnableSecureEventInput`). If something has secure input on, the event tap sees no keys at all. Step 2 checks with `ioreg -l -w 0 | grep -i SecureInput` while Plex is in front.

### Kiosk lock (item 6)

- `NSApplication.PresentationOptions`: `.disableProcessSwitching` (⌘Tab and ⌘⇧Tab), `.disableForceQuit` (⌥⌘Esc) and `.disableHideApplication` (⌘H) apply **only while MMTVL is the active app**. `.disableProcessSwitching` and `.disableForceQuit` must be combined with `.hideDock` or `.autoHideDock`. An invalid combination throws `NSInvalidArgumentException` ([kiosk thread](https://developer.apple.com/forums/thread/111064), [option rules summary](https://pub-web.flutter-io.cn/documentation/macos_ui/latest/macos_ui/NSAppPresentationOption.html)). MMTVL already uses `[.hideDock, .hideMenuBar]`, so adding them is valid.
- With another app in front (Plex, a web app), those options don't apply. Keyboard Maestro intercepts ⌘Tab with a **head-inserted session event tap**, which runs before the system switcher: "Cmd-Tab is not a real hot key" ([Keyboard Maestro forum](https://forum.keyboardmaestro.com/t/the-application-switcher-hotkey-sometimes-triggers-the-os-x-app-switcher/5912)). MMTVL's `GlobalEventTap` is exactly that kind of tap. Whether consuming ⌘Tab there really stops the switcher on macOS 26/27 is **unverified** (Q19, step 4). **Secure Keyboard Entry** (password fields, some terminals) blocks taps, so a tap alone can't be the whole lock.
- The backstop that doesn't depend on keys: watch `NSWorkspace.didActivateApplicationNotification`. When an app MMTVL didn't open comes forward, take the screen back. Only `.regular` apps count. Accessory and UI-element agents (Notification Center, SecurityAgent, AirPlay, screenshot UI) are never fought.
- ⌘Q quits MMTVL from the SwiftUI app's default menu (`MMTVLApp` has `Settings { EmptyView() }`). The Dock's Quit and a logout/shutdown also go through `applicationShouldTerminate(_:)`. `NSWorkspace.willPowerOffNotification` fires before a logout, restart or shutdown.

### Browser tile (item 4)

- Chromium and Safari have **View → Always Show Toolbar in Full Screen** (⇧⌘F in Chrome and Brave). Each browser saves the setting in its own preferences. Without it, a full-screen browser hides its tabs and address bar until the pointer touches the top edge, and a remote never does that. The exact menu title in Brave and Safari on macOS 26/27 is **unverified** (step 5 checks it). An AX menu item reports a check mark through `kAXMenuItemMarkCharAttribute` (`"✓"`, or nil/empty when unchecked) and is pressed with `kAXPressAction`.
- **Step 5 spike (2026-10-09, dev Mac, Brave):** View holds "Always Show Bookmarks Bar", **"Always Show Toolbar in Full Screen"**, "Always Show Full URLs", "Show Tabs Vertically", …; read through System Events, the toolbar item's `AXMenuItemMarkChar` is missing (unchecked) on this Mac. Safari wasn't running and wasn't checked; its title stays unverified (the prefix match logs "notFound" if it differs).
- Whether Chromium's `--start-fullscreen` honors that setting is **unverified** (step 5). Fallback: drop `--start-fullscreen` for the browser tile only and rely on `AXFullScreen` (D15), which is the same native full screen the menu item applies to.

### Live TV (item 7), Multiview (item 8)

- Player mode today (`LiveTVModel.handlePlayer`): Select opens the guide, and Back hides the overlays or else **leaves** Live TV. In the guide, `GuideModel` returns `.close` on Back, and `handleGuide` then returns to the player when something is playing. The M4 plan's command table (M4 §L9) is the spec being changed.
- Multiview: `MultiviewLayout.gap = 8` insets every slot by 4 points (except Picture in Picture's main window). The focus highlight is a 6-point `strokeBorder`, drawn inside the slot, so a gap of 0 still shows it.

### Home backdrop (item 9), Plex carousel and Live TV preview (item 10)

- `ShelfBackdrop` (`Launcher/TopShelfView.swift`) draws a **420-point icon** at (1440, 300) through `foreground {}` for `.designed`, `.icon` and `.gradient` art. That big icon is what gets in the way.
- Plex Continue Watching: `PlexAPI.card` already picks `grandparentArt ?? art ?? thumb` for episodes and `art ?? thumb` for movies. Those are 16:9 backdrops, fetched through `photo/:/transcode` at 704 × 396 (`PlexAPI.imageSize`). The same path at **1920 × 1080** suits a full-screen backdrop. `ShelfImageLoader` downsamples to 704 px (`maxPixelWidth`) and keeps 60 images.
- **Step 9 (2026-10-09):** the "Continue Watching item fields" line is a debug message and isn't kept in the log store, so it couldn't be read on the dev Mac. `Image: [{type, url}]?` is decoded anyway (leniently: a missing or odd field reads as nil), so a server that has clear logos shows them and one that doesn't shows the title. Q20 stays open until the user runs the Plex `log stream` from CLAUDE.md with `--level debug` while MMTVL loads Continue Watching.
- Plex "clear logo" art (a transparent title logo, in a Metadata `Image` array with `type: "clearLogo"` on newer servers) is **unverified** for the user's server. MMTVL logs the field names once at debug level ("Continue Watching item fields: …", M7 step 11). Step 9 reads that log line. Without a logo the title is drawn as text.
- Live TV: `LiveTVModel` owns `player` (pool player 0). `startMultiview(_:reusing:)` already keeps a playing channel's player when Multiview opens (M6 L12). `MPVPlayerController` holds a sleep assertion while loading or playing (`sleep.hold(...)`, `LivePlayer.swift:230`), so a preview left on the home screen would keep the Mac awake. `setAudible(false)` mutes a player without touching the phone's app volume (M6 L5).
- Streams: the provider allows 5 at once (Q10). A preview uses one only while the Live TV tile or one of its On Now cards has focus.

### Follow-ups found after the first build (added 2026-10-09)

- **Siri Remote double Select (item 12).** Through Remote Buddy, one Select enters two PIN digits and types two letters in YouTube search; selecting a video looks fine (the second Select lands while the player loads). Likely cause: macOS's GameController framework also sees the Bluetooth Siri Remote (a `microGamepad`), and `ControllerInput` maps its click (`buttonA`) to Select (`KeyBindings`: `controller(.a, .select)`), while Remote Buddy sends Return, a second Select. **Unverified**: the user tests with Settings → Remote & Input → Game Controllers → Off, and the `ControllerInput` log should show a "Controller connected: … (microGamepad)" line for the remote.
- **Siri Remote TV button on the mini (2026-10-10, build 15).** Settings → Remote Buttons → Home → Add a Button learned the TV button as **controller A** (GameController), and with Work in Other Apps it brings MMTVL back from other apps onto the start tile. Remote Buddy's Home-key mapping sent nothing MMTVL saw (no "Unbound key" line). The clickpad still selects normally (Remote Buddy's Return), so on this remote **A isn't the clickpad**, contrary to the double-Select guess above; that cause stays open (step 15). Consequence: Settings → Remote & Input → **Game Controllers must stay On**, or the TV button stops working as Home.
- **Browser tile was Safari (item 13).** On the dev Mac, `launch-items.json`'s `browser` tile was hand-edited to `{"application": {"bundleID": "com.apple.Safari"}}`, so it opened Safari, not the default browser (Brave), and L10 (toolbar) never ran for it (L10 covers `.defaultBrowser` and `.url` tiles). Fixed by hand on the dev Mac (backup `launch-items.json.before-browser-fix`); the mini's file needs the same check.
- **Custom tile pictures are clipped (item 14).** `TileArtView` draws `.picture` with `scaledToFill()` + `clipped()`, so a picture that isn't 5:3 loses its edges. The home backdrop (`ShelfBackdrop`) also fills, which is right for a full-screen background.
- **Prime Video: Back left it windowed (item 15).** MMTVL makes Prime Video native full screen (D15, `launchFullScreen`). Esc (the remote's Back through Remote Buddy) is also macOS's "exit full screen" key in many apps, so at Prime's top level Back took the window out of full screen onto the desktop Space instead of returning to MMTVL. **Unverified on the mini:** whether Esc during playback or in Prime's menus also exits full screen (if it does, "leaving full screen = go Home" would be wrong there), and whether Prime is a Catalyst app (not installed on the dev Mac).
- **Closing a web app stranded the screen (item 19, 2026-10-09, on the mini).** After closing the Google Photos web app (Brave), an empty full-screen Space stayed in front and ⌘Q did nothing (the kiosk lock only lets ⌘Q reach MMTVL, and ⌘Tab/⌃arrows are blocked while another app is in front). The keyboard Home key (fn+←) or the phone's Home is the way out. Likely the same family as Prime Video's Back (item 15): MMTVL doesn't notice that the app it opened left full screen or lost its last window. Investigate with step 17.
- **Black screen after leaving Plex (item 20, 2026-10-09, build 6, on the mini).** After watching a movie in Plex HTPC and exiting, the screen went black and the user couldn't get out. The mini's log isn't available, and the lines that would explain it (launches, quits, the foreground ladder, the kiosk guard) were info level, which macOS doesn't keep. Two candidates: (a) Plex itself still in front with a black window (its player didn't come back), with the Siri Remote lent to Plex by HIDRemote (Q21) so the remote's Home never reached MMTVL; (b) like item 19, an empty full-screen Space left in front. Also found: when a launched app quits, L5 only came back if MMTVL, nothing or the dead app was frontmost, but macOS makes **Finder** frontmost when a full-screen app quits, so MMTVL stayed behind unless the kiosk guard caught Finder (step 32). **The mini's log (2026-10-10, build 6, a second time):** Plex quit (00:37:20), MMTVL was frontmost 268 ms later, and over the next minutes the phone connected and a Live TV channel played (player 1), but the TV still showed Plex's last frame. So candidate (b): MMTVL active and working, its window on the desktop Space, the screen left on Plex's dead full-screen Space. Home couldn't help, since MMTVL was already frontmost (step 33). Refresh-rate switching was off in Plex and the TV isn't HDR.
- **Tile art (item 21, 2026-10-10).** A picture added to FaceTime couldn't be removed or replaced from Settings (the old picture stayed); a YouTube logo picture filled the tile edge to edge with no padding; the default art should look more like tvOS's flat brand tiles (user's tvOS screenshot) so custom pictures are needed less. See L33, step 34.
- **An own Siri Remote driver instead of Remote Buddy (item 16, question).** What exists: `ControllerInput` already reads the Siri Remote through GameController (the double-Select finding), with background monitoring in kiosk mode; `SyntheticInput` already posts keys to other apps (M5 L6). What's unknown: which buttons GameController exposes on macOS (on tvOS the TV button is reserved for the system; Back is `buttonMenu`, the clickpad is the `dpad` and `buttonA`), whether the TV button and Siri button reach a normal app at all (raw HID through `IOHIDManager`, which needs the Input Monitoring permission), and whether macOS also acts on Play/Pause and volume. Upside: no Remote Buddy, and no HIDRemote "lending" to Plex (Q21 disappears). Rough size: a spike of a day; if the TV button is readable, a milestone about M5's size (HID reader, mapping into `RemoteCommand`s, touch-surface swipes, routing to other apps through `SyntheticInput`, Bluetooth reconnect and sleep). If it isn't, the TV button can't be Home without Remote Buddy or a long-press/other-button compromise.

### Live TV speed after the first M7c build (item 18, added 2026-10-09)

The user tested the Release build on the mini: the Plex carousel works; on Live TV, **channel logos load slowly and aren't cached**, the **preview takes a while** after moving onto the Live TV tile, and **channel logos and stream starts feel much slower than before** this build (their provider's own website starts instantly). Findings from the code (no measurements yet, the mini is remote):

- **Logos were never cached by MMTVL.** All four logo sites (guide rows, the player's banner, the Live page info, the old On Now cards) use SwiftUI `AsyncImage`, which keeps nothing in memory and relies on `URLCache.shared` (small, and only when the logo host sends cache headers). Each guide row that scrolls back into view, and each Live page, fetches its logo again.
- **The preview starts late by design:** 0.8 s of focus (`previewDelay`) before `startPreview`, then the stream's own start. Leaving Live TV stops the stream (`leave()` releases every player), so coming home starts it again from cold.
- **Possible causes of the slowdown, unconfirmed:** extra connections from the preview (each Home visit and each page change opens a stream; the provider allows 5, Q10), and the main thread being busier (mpv's frames are drawn on the main thread, `isAsynchronous = false`, under the Liquid Glass home screen). Nothing in Live TV's own play/zap path changed in M7c apart from the preview adopt. The player logs "Loading a stream" and the decoder at **info** level, which isn't kept in the log store, so there's no timing to compare. Step 26 adds it.

**Measured on the dev Mac (2026-10-09, after build 3):** 1.0 takes the same 3.2–3.5 s per channel as build 3 (same log lines, five zaps each), so M7c didn't cause it. Hardware decoding, no retries, one load per press. A throwaway probe (mpv with no window or sound, the real playlist, timings only) and one redacted mpv debug log showed where ~2.7 s goes:
- 0.00–0.88 s: mpv opens the channel URL: the provider's `iptv.example` answers **302 after ~0.5 s of server time** to a Fastly CDN address, then the master playlist.
- 0.88–1.76 s: **ffmpeg's HLS demuxer opens the same URL again**: the same 302 and master playlist, ~0.88 s spent twice.
- 1.76–2.74 s: the video and the separate audio playlist, then a segment of each, one after another, **each on a new TLS connection** (~0.2 s apiece; ffmpeg doesn't reuse them).
- Plain HTTP (URLSession) gets the 302 + playlists + first segment in ~0.8 s. Decoding is milliseconds.

Probe results (time to first frame, four channels): baseline 2.7–3.1 s; `lavf://` prefix no better; **redirect resolved with URLSession first (included) 2.0–2.4 s**; **plus `demuxer-lavf-o=http_multiple=0` 1.7–2.0 s**; **a CDN address resolved 60 s earlier, reused: 1.4–2.0 s** (still valid after 60 s). The remaining ~1.4 s is ffmpeg's serial new connections, which MMTVL can't change without replacing the player.

## Design

### Local decisions

- **L1 — Foregrounding ladder (D35).** A new `App/Foregrounder.swift` brings MMTVL forward and **checks that it worked**: rung 1 `NSApp.activate()`; after `checkDelay` (250 ms), if `NSWorkspace.shared.frontmostApplication?.processIdentifier != getpid()`, rung 2 is AX `kAXFrontmostAttribute`; after another check, rung 3 hides the frontmost app if it's a `.regular` app other than MMTVL. Each rung logs at info, category **`Foreground`** (rung, front app bundle id, success). Step 2 records which rung works per app and may reorder the rungs or drop one. It also decides whether the collection-behavior option (findings, item 4) is needed, as a constant in `KioskWindowController`.
- **L2 — Every "show MMTVL" goes through the ladder:** global Home, wake, a launched app quitting (`onReturnToLauncher`), the end of a mirroring session, a YouTube cast, and the kiosk guard (L8). `KioskWindowController.show()` keeps ordering the window front and setting presentation options. It then calls `Foregrounder.bringForward()` instead of `NSApp.activate()`. The presentation options are applied again once activation is confirmed, because they only take effect while MMTVL is active.
- **L3 — A visible but inactive window is repaired.** Phone commands arriving while MMTVL isn't active, with its kiosk window on screen and the frontmost app being nil, Finder or MMTVL (the item 3 state), run `bringForward()` first. The command is then dispatched to MMTVL instead of posted as a synthetic key. `PhoneRemote` gets this through a new environment closure, `repairForeground() -> Bool`.
- **L4 — Esc stays Back** in other apps (user choice 2026-10-09). No change to bindings.
- **L5 — Siri Remote through Remote Buddy:** map the TV/Home button to the keyboard **Home** key (key code 115) in Remote Buddy's global (all-apps) behavior. That's MMTVL's default global Home binding, and the event tap consumes it, so apps never see it. Map Back/Menu to **Escape**, Select to **Return**, the arrows to the arrow keys, Play/Pause to the media play/pause key, and the volume buttons as Remote Buddy likes. If Remote Buddy sends something else, *Settings → Remote Buttons → Home → Add a Button* learns it, and *Work in Other Apps* makes it global (D27). This goes in CLAUDE.md and is checked in step 13.
- **L6 — Kiosk lock (D36)** is on in kiosk mode while MMTVL hasn't been exited to the desktop, and when `settings.json` **`kioskLock`** (default `true`; Settings root → *Keep Other Apps Out*) is on. It is off in `-windowed` mode and after Exit to Desktop until Home brings MMTVL back. It is off when global input is off (no event tap, so no Home to come back with). It has three parts: L7, L8 and L9.
- **L7 — While MMTVL is active:** presentation options `[.hideDock, .hideMenuBar, .disableProcessSwitching, .disableForceQuit, .disableHideApplication]`. Not `.disableSessionTermination` (it would block shutdown) and not `.disableAppleMenu` (the menu is hidden anyway).
- **L8 — With another app in front:** (a) the event tap consumes these shortcuts: ⌘Tab, ⌘⇧Tab, ⌘\` (any modifiers that include ⌘ with Tab or \`), ⌘Space, ⌥⌘Esc, and ⌃↑/⌃↓/⌃←/⌃→ (Mission Control and Spaces). They're a static list, `KioskLock.blockedShortcuts`, and not in `key-bindings.json`. (b) **Kiosk guard:** when a `.regular` app that isn't allowed becomes active, MMTVL takes the screen back exactly like Home (`launcher.homePressed(); router.goHome(); show()`). Allowed apps: MMTVL; the bundle ids of the app MMTVL opened since the last Home (the tile's app, the default browser, a web app's shim and its `CrBundleIdentifier` browser); Reflector (D32); System Settings while MMTVL opened it (Accessibility onboarding, Settings → Casting → AirPlay, Login Items), until the next Home. The guard has a rate limit: after 3 takebacks in 10 s it logs and stops until the next Home, so it can never fight an app forever. Logs use category `KioskGuard` (bundle ids only).
- **L9 — Quitting MMTVL needs the PIN.** `applicationShouldTerminate` returns `.terminateCancel` when the lock is on and termination isn't allowed. The router then asks for the PIN with a new purpose, `PINPurpose.quit`, and quits after it, or quits straight away when no PIN is set. Termination is always allowed after `willPowerOffNotification`, from *Relaunch MMTVL* (`AppRelauncher`), and when the lock is off. This covers ⌘Q and the Dock's Quit.
- **L10 — Browser toolbar.** For `.defaultBrowser` and `.url` tiles that want full screen, after `makeFullScreen`, `BrowserToolbar.ensureShown(pid:)` finds the app's AX menu bar → **View** → the item whose title starts with "Always Show Toolbar in Full Screen". If its mark char is empty, it presses it. If it's checked, or there's no such item, it does nothing (logged). It never runs for web app tiles.
- **L11 — Live TV Back and Select** (user choice 2026-10-09). Player: Back hides the banner or bar if shown, otherwise **opens the guide**.
